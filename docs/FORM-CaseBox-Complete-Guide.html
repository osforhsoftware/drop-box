1. Platform Overview

CASEBOX is a full-stack custom phone case e-commerce platform. Customers can design their own cases or buy pre-made templates from the Shop. Orders are paid via UPI with manual screenshot verification.

Core Capabilities

AreaFeatures
Customer Custom designer (Fabric.js), template shop, user accounts, checkout, UPI payment, order tracking, wishlist
Admin Orders, catalog (brands/models/case types), case overlay templates, shop template products, promo codes, popup offers, settings
Backend Node.js + Express + MongoDB, JWT auth, Multer file uploads (max 12 MB general), static serving at /api/uploads/

Tech Stack

  • Frontend: React 19, React Router 7, Tailwind CSS, Shadcn UI, Fabric.js, Framer Motion
  • Backend: Node.js, Express, MongoDB, Multer, JWT, bcryptjs
  • Payments: Manual UPI (QR code + screenshot + UTR verification)

2. Image Upload Size Guide

All uploads accept common web image formats unless noted. Server enforces hard file-size limits — stay under the recommended sizes for faster uploads and better performance.

Global allowed formats (most uploads): JPG, JPEG, PNG, WEBP, GIF

Best Practices

  • Shop thumbnails: Center the phone case on a dark (#111111) or transparent background. Avoid busy backgrounds — cards crop to 5:4.
  • Customer artwork: Upload the highest quality source you have. The canvas scales down for preview but the original is used for printing.
  • Case overlay PNGs: Use a clean phone outline with transparent areas for camera cutouts. PNG only — no JPEG.
  • Compress before upload: Use TinyPNG, Squoosh, or export at 80–90% JPEG quality to stay under recommended sizes without visible quality loss.
  • Payment screenshots: Ensure UTR/reference number and amount are legible. Full-screen UPI success screen works best.

2b. Demo Catalog Seeding

Use the backend seed scripts to populate the Shop with demo phone cases and expand Customize frame overlays for priority phone models. Safe to re-run — existing demo-* products are skipped.

Commands

cd backend
npm run generate:demo-images # creates 800×640 thumbnails in scripts/demo-images/
npm run seed:demo # inserts products + clones missing templates

What Gets Created

TypeAdmin PageCountImage Spec
Phone Cases (Shop) Admin → Phone Cases 21 published demo products 800 × 640 px JPG · dark #111 background · slug prefix demo-
Phone Case Templates (Customize) Admin → Phone Case Templates Cloned for 8 priority models × 4 case types Transparent PNG frame · mask zones copied from source

Shop vs Template Images

  • Shop Phone Cases — product photos or styled thumbnails (JPG/PNG/WEBP). AI-generated or designed images work well. Replace anytime via Admin → edit product → upload new thumbnail.
  • Customize Templates — transparent PNG frame overlays only. AI mockup photos are rejected. Clone existing frames or export hollow phone outlines from a design tool.
After seeding: 6 demo products are marked Featured for the homepage slider. Spot-check cloned template mask zones in Admin → Zone Editor if camera cutouts look misaligned on a new phone model.

Configuration Files

  • backend/scripts/demo-catalog.json — product titles, categories, prices, featured flags, priority models
  • backend/scripts/demo-images/ — generated thumbnails (one per demo-* slug)
  • backend/scripts/seed-demo-catalog.js — idempotent MongoDB seeder

6. Order & Payment Flow

Home → Shop or Customize → Checkout → Payment (UPI) → Track Order

Custom Order Path

  1. Customer selects brand, model, case type in Customizer
  2. Uploads artwork and positions on Fabric.js canvas
  3. Design + preview PNG uploaded to backend; draft saved in sessionStorage
  4. Customer fills shipping at Checkout → order created (ID: FRM-YYMMDD-XXXXXX)
  5. Customer pays via UPI, uploads screenshot, enters UTR
  6. Admin verifies payment in Orders panel
  7. Customer tracks delivery on Order Status page

Template Shop Path

  1. Customer browses Shop, picks pre-designed template
  2. Selects phone model on Template Detail page
  3. Checkout → Payment → Track (same as custom)

7. API & Technical Reference

Base URL: {BACKEND_URL}/api (default: http://localhost:8000/api)

Upload Endpoints

MethodEndpointAuthPurpose
POST/upload/design—Customer artwork
POST/upload/preview—Canvas preview PNG
POST/upload/paymentUserPayment screenshot

Static files served at: /api/uploads/{designs|payments|templates|brands|models|products|template-products|popups}/<filename>

Environment Variables

Backend (.env)

  • MONGO_URL — MongoDB connection
  • DB_NAME — Database name
  • JWT_SECRET — Token signing
  • ADMIN_EMAIL / ADMIN_PASSWORD
  • PORT — default 8000
  • PUBLIC_BASE_URL — upload URL prefix

Frontend (.env)

  • REACT_APP_BACKEND_URL — API base URL

Getting Started

# Backend
cd backend && npm install && npm start

# Frontend
cd frontend && npm install && npm start

# Admin login at http://localhost:3000/admin/login
